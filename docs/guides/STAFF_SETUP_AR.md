# المرحلة الأولى: المالك والإدارة والدعم

هذه ملفات كاملة فوق آخر نسخة من RIVO بعد السياسات. خذ نسخة احتياطية من الملفات المطابقة وقاعدة البيانات. لا تستبدل wrangler.json أو مفاتيح Supabase أو المورد. لم يُنشر التحديث أو تُعدّل صلاحيات حسابك الحي من هنا.

## التثبيت

انسخ الملفات بنفس المسارات إلى rivo-cloudflare، ثم نفذ:

```powershell
npm test
npm run db:remote
npm run deploy
```

الترحيل الجديد 0009_staff.sql يضيف جدول صلاحيات الموظفين وملاحظات الدعم، ويعيّن المالك فقط للحساب الموجود بالفعل بمعرّف:

```text
supabase:9fe15a87-5c6a-4575-839d-5bf4905aef6e
```

افتح /api/session بعد النشر بنفس حسابك وتحقق أن role أصبحت owner. للتحقق من قاعدة البيانات:

```powershell
npx wrangler d1 execute DB --remote --command "SELECT user_id,role,active FROM staff_access WHERE role='owner';"
```

إذا النتيجة فارغة توقّف وأرسل نتيجة الاستعلام؛ لا تغيّر أدوار حسابات عشوائية. الترحيل لا ينشئ حساب Supabase جديدًا، بل يربط حساب المستخدم الموجود. صلاحيات Supabase الإدارية ومفاتيحها لا تُستخدم أو تُمنح للموظفين.

## إدارة الفريق

ادخل /admin ثم اضغط Ctrl+F5. للمالك يظهر قسم «إدارة الفريق»؛ ابحث بالإيميل أو الاسم أو معرّف الحساب. يعرض البحث حتى 100 حساب مطابق؛ استخدم الإيميل الكامل عند كثرة النتائج.

الموظف يسجّل حسابه بنفسه أولًا. تحقق من إيميله ومعرفه قبل تغيير دوره. يوجد:

- owner: حسابك؛ إدارة الفريق وكل وظائف المتجر. لا يمكن تخفيض المالك نفسه أو تعيين مالك إضافي من الواجهة في هذه المرحلة.
- admin: خصص له المنتجات، إدارة الطلبات، إعدادات المتجر، الموردين والتنفيذ، أو نشر السياسات. إدارة الطلبات تتضمن العمليات اليدوية الحالية، لذا لا تمنحها لموظف الدعم. صلاحية الموردين تسمح بالتنفيذ الحقيقي وفق حمايات الدفع والتأكيد الحالية.
- support: مكتب دعم لقراءة الطلبات والبحث برقمها أو الرابط أو الزبون أو المنتج، وإضافة ملاحظات دعم داخلية. لا تعديل للدفع أو الأسعار أو تنفيذ للمورد، ولا أكواد تسليم أو بيانات تكلفة وربح أو ملاحظات الإدارة الخاصة.
- customer: حساب زبون فقط.

إلغاء «تفعيل وصول الموظف» يعطّل الوصول الوظيفي ويعيد معاملته كزبون؛ لا يحذف الحساب ولا يمنع الشراء. تُقرأ الصلاحيات من قاعدة البيانات مع طلبات الحساب، لا من بيانات Supabase التي يعدّلها المستخدم. الموظف قد يحتاج تحديث الصفحة لتتغير واجهته؛ الخادم يمنع العملية غير المسموحة حتى قبل ذلك.

المديرون السابقون الذين لم تخصص لهم صفًا في staff_access يحتفظون بصلاحياتهم السابقة. خصص صلاحياتهم من إدارة الفريق لتقييدها. لا يوجد إرسال دعوة أو كلمة مرور من هذه الشاشة.

## تجربة الدعم

عيّن حسابًا ثانيًا support، ثم سجّل الدخول به في نافذة منفصلة: يجب فتح مكتب الدعم عند /admin. ابحث عن طلب وأضف ملاحظة؛ لا تظهر ملاحظات الدعم للزبون. الإدارة المخولة بعرض الطلب تشاهد ملاحظات الدعم عند فتحه.

هذه المرحلة ليست الشات: لا يوجد بعد استلام محادثات أو قائمة انتظار أو زر تصعيد أو بوت. الملاحظات تساعد المتابعة الآن، ثم نضيف المحادثات والتحويل للإدارة فوق نظام الأدوار. صلاحيات عرض الأكواد للدعم غير مضافة؛ تبقى الأكواد محجوبة عنه.

اختبر حساب الأدمن المحدود للتأكد من منع الأقسام غير الممنوحة، وحساب الدعم للتأكد من منع تعديل الطلبات أو الفريق. مفاتيح البوابة والمورد تبقى في Cloudflare، ولا توجد صلاحية تعرض قيمها في الواجهة. سجل النشاط يسجل تغييرات الفريق وإضافة ملاحظات الدعم دون نص الملاحظة.

لم تُنفّذ معاينة بمتصفح لهذا الإصدار؛ راجع الواجهات عندك بعد النشر. تغييرات هذه الحزمة محلية فقط، ولا تغيّر إعدادات الدفع الحقيقي أو مشكلة رجوع Payunit المؤجلة.
