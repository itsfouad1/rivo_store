# تفعيل Payunit في RIVO

هذه ملفات كاملة معدّلة فوق نسخة RIVO متعددة العملات والمربوطة بـFoxReload. لم يتم نشرها على حسابك ولم يحدث دفع فعلي. خذ نسخة احتياطية من مجلد مشروعك وقاعدة البيانات قبل التحديث. إذا عدّلت الملفات بعد النسخة السابقة، ادمج التغييرات بدل استبدال تعديلاتك الخاصة.

## طريقة العمل

- يبقى عرض الأسعار بالعملة التي يختارها الزبون، وتُنشأ فاتورة Payunit بالدولار USD.
- يحفظ الخادم مبلغ الدولار وأسعار الصرف مع الطلب. تظهر صفحة مراجعة مبلغ الدولار قبل الانتقال للبوابة. لا يتغير المبلغ عند إعادة المحاولة.
- إعادة المحاولة لنفس الطلب تستخدم مفتاح Idempotency ثابتًا. لا تنشئ طلبًا جديدًا لمعالجة انقطاع اتصال سابق؛ افتح الطلب من حسابك.
- الرجوع من البوابة وحده لا يعني نجاح الدفع. إشعار موقّع يتبعه استعلام مباشر عن الفاتورة، أو زر «تحديث حالة الدفع»، يؤكد النتيجة والمبلغ من Payunit.
- وضع test مخصص لحساب الأدمن. الدفع التجريبي لا يسمح بشراء منتج حقيقي من FoxReload.
- بعد الدفع الحقيقي يصبح الطلب بانتظار التنفيذ. تنفيذ FoxReload يبقى يدويًا من الإدارة مع الحمايات الحالية؛ لا توجد عملية شراء تلقائية جديدة.
- إشعارات الاسترداد الكامل أو الجزئي توقف الطلب للمراجعة. بدء استرداد المال نفسه يتم من Payunit وليس من لوحة RIVO. تنفيذ منتج سبق تسليمه لا يُعكس تلقائيًا.

## 1. نسخ الملفات

فك ضغط الحزمة داخل مجلد rivo-cloudflare مع الحفاظ على مسارات lib وpublic وmigrations وtests. استبدل الملفات المطابقة بعد النسخ الاحتياطي. الحزمة لا تحتوي wrangler.json، فلا تستبدل إعدادات الحساب أو قاعدة البيانات أو Supabase الموجودة عندك.

داخل قسم vars في wrangler.json أضف هذا المفتاح مع الحفاظ على بقية القيم والفواصل الصحيحة:

```json
"PAYUNIT_MODE": "test"
```

إذا لم تضفه فالافتراضي test أيضًا. لا تغيّر FOXRELOAD_LIVE_ENABLED لأجل اختبار الدفع.

## 2. مفاتيح الاختبار

من Payunit أنشئ مفتاح API اختباريًا يدعم إنشاء الفواتير وقراءة حالتها. يحتاج الربط GET /invoices/{id} إضافة إلى POST /invoices. لا ترسل المفاتيح في المحادثة ولا تضعها في public أو GitHub.

من PowerShell داخل مجلد المشروع:

```powershell
npx wrangler secret put PAYUNIT_API_KEY
```

ألصق مفتاح الاختبار الذي يبدأ بـpay_test_ عند الطلب.

أضف عنوان Webhook في بيئة اختبار Payunit:

```text
https://rivo-store.rivo1.workers.dev/api/webhooks/payunit
```

واختر الأحداث:

```text
invoice.paid
payment.failed
payment.refunded
```

احفظ Webhook وخذ سر التوقيع الخاص به، ثم:

```powershell
npx wrangler secret put PAYUNIT_WEBHOOK_SECRET
```

ألصق سر التوقيع عند الطلب، وليس مفتاح API. إذا لم يسمح Payunit بحفظ العنوان قبل توفره، انشر الملفات أولًا ثم أكمل إعداد Webhook والسر. ستبقى البوابة غير جاهزة حتى تكتمل المفاتيح.

## 3. الاختبار والنشر

```powershell
npm test
npm run db:remote
npm run deploy
```

طبّق الترحيل الجديد 0006_payunit.sql على قاعدة RIVO الصحيحة قبل استخدام الكود الجديد. لا تحذف الترحيلات السابقة ولا تغيّر معرّف قاعدة البيانات. في حال فشل الاختبارات أو الترحيل، توقّف قبل النشر وأرسل رسالة الخطأ بدون أسرار.

## 4. تجربة كاملة بحساب الأدمن

1. سجّل الدخول بحساب الأدمن واجعل طريقة دفع منتج «بوابة الدفع» أو «كلاهما».
2. افتح المتجر، اختر العملة، وأضف المنتج ثم اختر بوابة الدفع.
3. راجع مبلغ الدولار الظاهر واضغط الانتقال للدفع. ستُنشأ فاتورة test.
4. استخدم آلية المحاكاة الرسمية في بيئة اختبار Payunit لتجربة النجاح والفشل. لا تستخدم وسيلة دفع حقيقية في هذه الخطوة.
5. ارجع لصفحة الطلب واضغط «تحديث حالة الدفع» إذا تأخر Webhook. يجب أن تظهر نتيجة تجريبية، ولا يبدأ شراء حقيقي من المورد.
6. راجع سجل Webhook في Payunit: الطلب الصحيح يرجع HTTP 200. خطأ 503 قد يعني وصول الإشعار قبل حفظ معرّف الفاتورة أو تعذر استعلام البوابة؛ يُعاد إرساله.
7. اختبر إعادة فتح الطلب، ومنع دخول حساب آخر إليه، وإلغاء فاتورة غير مدفوعة ثم تحديث حالتها.

الاختبارات الآلية تستخدم ردودًا محاكية لـPayunit. لم تُجرَ تجربة فعلية على حساب Payunit. إذا اختلف شكل استجابة API أو محتوى Webhook الفعلي عن الدليل، أرسل الرد بعد إزالة الأسرار وبيانات العملاء لنضبط التوافق. لا تنتقل إلى live قبل نجاح هذه التجربة.

## 5. الانتقال للدفع الحقيقي بعد نجاح الاختبار

- أكمل تفعيل حساب التاجر وقبول USD لدى Payunit. اختيار USD هنا يحدد عملة الفاتورة؛ إعدادات تسوية رصيد التاجر ورسومه تبقى في Payunit.
- أنشئ Webhook في البيئة الحقيقية لنفس العنوان والأحداث، واستخدم سرّه الحقيقي.
- استبدل PAYUNIT_API_KEY بمفتاح pay_live_، واستبدل PAYUNIT_WEBHOOK_SECRET بسر البيئة الحقيقية.
- غيّر PAYUNIT_MODE إلى live داخل vars ثم نفّذ npm run deploy. نفّذ تبديل إعدادات البيئة خارج وقت استقبال طلبات جديدة.
- يصبح الدفع متاحًا للزبائن بعد اكتمال المفاتيح المتطابقة. الطلبات التجريبية لا تتحول لفواتير حقيقية؛ أنشئ طلبًا جديدًا.
- لا تعدّل حالة الدفع إلى «مدفوع» يدويًا. تأكيدها يأتي من البوابة. لإلغاء فاتورة غير مدفوعة ألغها من Payunit ثم حدّث الحالة.

مرجع الواجهة: https://payunit.co/en/developers، مع دليلي Payunit المرفقين في المحادثة.
