# ربط FoxReload بمتجر RIVO

حزمة ملفات كاملة مبنية على مستودع itsfouad1/rivo_store، فرع main، commit:
`a15e02bc1985b23e712ea92a528d13f71336c638`

لم يتم تعديل GitHub أو نشر التغييرات أو الاتصال بحسابك لدى المورد. الاختبارات تستخدم موردًا وهميًا؛ تجربة حساب FoxReload الفعلية تأتي بعد الإعداد.

## 1. نسخ الملفات

احفظ نسخة احتياطية من مجلد المشروع. انسخ محتويات مجلد `rivo-cloudflare` الموجود في ZIP إلى مجلد مشروعك الحالي ووافق على استبدال الملفات المطابقة. الملفات المرفقة كاملة؛ لا يلزم لصق أجزاء من الكود.

الحزمة لا تستبدل إعدادات تسجيل الدخول، ولا ملف wrangler.json الخاص بك، ولا صورك. تحافظ أداة الإعداد على ربط قاعدة البيانات وR2 ومتغيرات Supabase الحالية.

من PowerShell داخل مجلد المشروع:

```powershell
node scripts/update-foxreload-config.mjs
npm test
npm run db:remote
npx wrangler secret put FOXRELOAD_API_KEY
npm run deploy
```

أدخل مفتاح FoxReload عند طلبه من Wrangler. إذا كنت أضفته بالفعل، لا يلزم تكرار خطوة المفتاح. يضيف الترحيل 0004 جداول الربط دون حذف المنتجات أو الطلبات القديمة. لا تغيّر ملفات الترحيلات السابقة.

## 2. تجربة الكتالوج

افتح `/admin#foxreload` بعد الدخول بحساب الأدمن. اضغط «عرض الرصيد» للتأكد من المفتاح، ثم «عرض المنتجات». يمكنك إدخال معرّف/slug تصنيف اختياري للبحث داخل شجرته، والتنقل بين صفحات الكتالوج.

استورد المنتج كمسودة، وحدد نسبة الزيادة على تكلفة المورد. مثال: تكلفة 10 دولارات + زيادة 20% = سعر بيع 12 دولارًا، وليست نسبة هامش من إجمالي المبيعات. أسعار التكلفة تحفظ بدقة أربعة منازل عشرية، وسعر البيع يقرّب للأعلى إلى السنت.

من صفحة المنتجات عدّل الاسم والوصف للعربية والمنطقة والصورة ثم انشر. اختر طريقة الدفع لكل منتج كالمعتاد. بوابة الدفع لا تزال غير مربوطة؛ الطلب عبر واتساب يعمل، والتحصيل يتطلب تأكيدك اليدوي.

المزامنة تحدّث أقدم 10 منتجات مربوطة كل 15 دقيقة؛ 30 منتجًا تحتاج نحو 45 دقيقة للمرور عليها كلها. يتم تحديث 10 عمليات معلقة في كل دورة أيضًا. يمكنك تحديث المنتج من «الربح والتحديث». يحافظ التحديث على الاسم والوصف والصورة. عند تفعيل التسعير التلقائي يستبدل سعر البيع بالدولار، وعند إيقافه يبقى سعر البيع اليدوي. لا يوجد تحويل آلي للشيكل/الدينار.

## 3. إعداد Webhook بعد النشر

المسار المضاف:
`https://rivo-store.rivo1.workers.dev/api/webhooks/foxreload`

الحدث المدعوم هو `order.completed`. لا تسجّل الرابط قبل نشر الكود. الأوامر التالية تطلب مفتاح المورد بإدخال مخفي، تسجّل الرابط، ثم تحفظ سر التوقيع في Cloudflare دون عرضه:

```powershell
$foxSecret = Read-Host "FoxReload API key" -AsSecureString
$foxPlain = [System.Net.NetworkCredential]::new('', $foxSecret).Password
$foxPlain | node scripts/setup-foxreload-webhook.mjs
Remove-Variable foxPlain, foxSecret
```

إذا كان الرابط مسجلًا سابقًا، الأداة تتوقف لتجنب التكرار. استخدم سر التوقيع الموجود لديك:

```powershell
npx wrangler secret put FOXRELOAD_WEBHOOK_SECRET
```

إذا فشل حفظ السر في Cloudflare بعد إنشاء الرابط، تحتفظ الأداة به مؤقتًا في `.foxreload-webhook-secret` (مستثنى من Git). أعد تشغيل `node scripts/setup-foxreload-webhook.mjs` بعد إصلاح تسجيل دخول Wrangler، فتحفظ السر وتحذف النسخة المؤقتة. لا تشارك هذا الملف. الإشعارات تتحقق من توقيع HMAC والتوقيت، وتتجاهل تكرار الحدث.

## 4. اختبار الطلب

أنشئ طلبًا جديدًا من المتجر لمنتج مستورد. افتحه من الأدمن، ثم «تنفيذ / متابعة منتجات FoxReload». اختَر «طلب تجريبي»، وأدخل بيانات الشحن المطلوبة كما يعرضها المورد بصيغة JSON، مثل:

```json
{ "login": "example_steam_login" }
```

للأكواد التي لا تحتاج بيانات، استخدم `{}`. الأرقام المطلوبة بصيغة integer/number تُكتب دون علامات اقتباس. بيانات الشحن تُؤكَّد مع الزبون عبر واتساب قبل التنفيذ. كل عنصر في الطلب له عملية مستقلة، ومعرّف ثابت يمنع إعادة الشراء عند الضغط مرة ثانية. الطلبات التجريبية ترجع أكوادًا وهمية ولا تظهر في مشتريات الزبون.

## 5. تفعيل الشراء الحقيقي بعد نجاح التجربة

في قسم `vars` من ملف `wrangler.json` غيّر:

```json
"FOXRELOAD_LIVE_ENABLED": "true"
```

ثم شغّل `npm run deploy`. هذا يتيح زر التنفيذ الحقيقي للأدمن، ولا يرسل طلبات شراء تلقائيًا بمجرد زيارة الزبون أو إنشاء طلب.

أكد استلام مبلغ الزبون فعليًا واحفظ حالة الدفع «مدفوع»، ثم افتح التنفيذ واختر «شراء حقيقي» وفعّل مربع تأكيد الخصم. التكلفة تُخصم من رصيدك لدى المورد بالدولار. يلزم أن يكون سعر بيع المنتج بالدولار وألا تقل قيمته عن تكلفة المورد. إذا ارتفعت التكلفة عن المحفوظ عند إنشاء الطلب، يتوقف التنفيذ للمراجعة.

عند اكتمال جميع عناصر الطلب لدى المورد تتحول حالة طلب ريفو إلى مكتمل. للطلبات المختلطة مع عناصر يدوية، أكمل الجزء اليدوي ثم حدّث الحالة بنفسك. تظهر أكواد العمليات الحقيقية لصاحب الطلب فقط من زر «عرض الأكواد ونتيجة الشحن». الشحن المباشر قد يعيد مراجع تنفيذ بدل أكواد تفعيل.

إذا انقطع الاتصال أثناء دفع المورد، نحدّث حالة الطلب ولا نكرر الخصم تلقائيًا. إذا ظل `active` مع عبارة «بدأت محاولة الدفع»، راجع الطلب لدى FoxReload قبل أي إجراء يدوي. الاسترداد إلى رصيد المورد لا يعيد مبلغ الزبون تلقائيًا؛ عالج رد أموال الزبون حسب وسيلة دفعه.

## نطاق هذه النسخة

- مدعوم: بطاقات وأكواد `code` وشحن مباشر `direct_topup` بكميات من 1 إلى 99، مع احترام حدود المورد.
- غير مدعوم هنا: `login_topup`، البطاقات البنكية، وeSIM. تُمنع هذه المنتجات من الاستيراد.
- المنتجات/الطلبات القديمة قبل الترحيل لا تُربط بأثر رجعي؛ استخدم الاستيراد المخصص للطلبات الجديدة.
- لا ترسل كلمة مرور حساب اللاعب؛ هذه النسخة تستبعد الشحن الذي يحتاج تسجيل الدخول إلى حسابه.
- إعداد IP allowlist عند المورد يجب أن يسمح باتصالات بيئة Worker؛ لا تستخدم عنوان جهازك باعتباره عنوان الخادم.
- لم تُجرَ تجربة شراء حقيقية أو طلب تجريبي على حسابك، ولا يوجد مفتاح مورد في الحزمة.
