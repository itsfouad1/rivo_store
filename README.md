# RIVO | ريفو

متجر شحن ألعاب وبطاقات رقمية، بهوية بنفسجية وسماوية. يعمل على Cloudflare Workers مع D1 وR2، ويستخدم Supabase Auth للحسابات، وFoxReload للمورد، وPayunit للدفع.

## خريطة المشروع

| المسار             | المحتوى                                                         |
| ------------------ | --------------------------------------------------------------- |
| `src/worker.mjs`   | نقطة دخول Worker، التوجيه والمهام الدورية                       |
| `src/lib/`         | منطق السيرفر: الحسابات، الطلبات، المورد، الدعم، العملات والبريد |
| `public/*.html`    | صفحات المتجر والإدارة؛ روابط الصفحات كما هي                     |
| `public/js/`       | JavaScript للمتجر ولوحات الإدارة والمكونات المشتركة             |
| `public/css/`      | التنسيقات                                                       |
| `public/assets/`   | الشعار؛ شخصية ريفو وfavicon محفوظان في public بروابطهما السابقة |
| `migrations/`      | ترحيلات D1 مرتبة؛ لا تحذف أو تعدّل ترحيلًا مطبقًا               |
| `tests/`           | اختبارات محلية بقاعدة SQLite مؤقتة وخدمات محاكاة                |
| `scripts/`         | أدوات الإعداد والنسخ الاحتياطي وفحص المسارات                    |
| `email-templates/` | قوالب تأكيد الحساب والاسترداد للصقها في إعدادات Auth            |
| `docs/guides/`     | أدلة الميزات والإعداد                                           |
| `docs/previews/`   | لقطات توضيحية سابقة؛ ليست بيانات المتجر الحية                   |
| `docs/archive/`    | وثائق ترحيل قديمة للمرجعية فقط                                  |
| `docs/brand/`      | وصف شخصية ريفو                                                  |

## التشغيل والفحص

Node.js 22.12 أو أحدث. افتح PowerShell داخل مجلد المشروع الذي يحتوي `package.json` و`wrangler.json`:

```powershell
npm ci
npm run check
npm test
npm run build
```

`check` يفحص المسارات والاستيرادات المحلية الثابتة. `build` يجمع Worker محليًا باستخدام dry-run ولا ينشر. لا يغني الفحصان عن تجربة الواجهة والخدمات الفعلية.

للتشغيل المحلي، طبّق الترحيلات المحلية فقط ثم شغّل Wrangler:

```powershell
npm run db:local
npm run dev
```

انسخ `.dev.vars.example` إلى `.dev.vars` إن احتجت إعدادات محلية، ولا ترفع ملف القيم الخاصة إلى GitHub.

## الإعدادات والنشر

`wrangler.json` يحتوي إعدادات المشروع الحالية. في نسخة موجودة حافظ على قيم حسابك وقاعدة البيانات وR2 والمتغيرات؛ التغيير التنظيمي المطلوب فيه هو `main: "src/worker.mjs"` فقط. لا تستخدم نسخة إعدادات قديمة لاستبداله.

النشر اليدوي بعد مراجعة الإعدادات:

```powershell
npm run backup
if ($LASTEXITCODE -ne 0) { throw "Backup failed" }
npm run db:remote
if ($LASTEXITCODE -ne 0) { throw "Migration failed" }
npm run deploy
```

`backup` يصدّر D1 فقط إلى `backups/`؛ لا يشمل صور R2 أو حسابات Supabase. النسخ قد تحتوي بيانات خاصة ولا ترفع إلى GitHub. لا يحتاج تنظيم الملفات إلى ترحيل SQL جديد؛ الترحيل 0016 مطلوب للميزات التي أضيفت سابقًا إذا لم يكن مطبقًا بعد.

إرسال إشعارات الطلبات بالبريد وتجربة الدفع الحقيقي مؤجّلان بقرار صاحب المتجر. تنظيم الملفات لا يفعّلهما ولا يغيّر مفاتيحهما. إعداد SMTP الخاص بتأكيد حسابات Auth موضوع منفصل عن إشعارات الطلبات.
